## Public archive validation: 2026-09-13

After the documentation and artifact-integrity packaging change, the standard
fixed-seed 1,000-document benchmark was rerun from the workspace parent with:

```sh
./Temp/thunderbird-ai-pipeline-lab/scripts/benchmark.sh \
  --name publication-validation-1000
```

It ingested 1,000 documents in 0.726 seconds (1,378 documents/second), measured
1.851 ms query p50 and 2.464 ms query p95, peaked at 34,064 KiB RSS, and wrote a
3,465,216-byte database. This run validates the publishable snapshot; it is not
a before/after optimization claim because the change is documentation and
packaging only. Machine-readable and review reports are retained in
`reports/publication-validation-1000.{json,md}`.

Optimization claims are recorded only with paired measurements. The current
deterministic baseline is generated by:

```sh
./scripts/benchmark.sh
```

The command writes machine-readable and Markdown results under `reports/` with
the corpus seed, document count, database size, wall/CPU time, peak RSS, query
latency, and throughput. Use `./scripts/benchmark.sh --full` for the fixed 1K,
10K, and 100K scale series. Hardware-specific results are artifacts and are not
treated as portable constants.

## Staged advanced-RAG evaluation: 2026-09-12

Command: `./scripts/run.sh rag-evaluate --name staged-rag-evaluation`.
The frozen 10-document/eight-case suite evaluates chunking and retrieval before
generation. All three chunkers preserved 100% source coverage and labeled-fact
integrity. At K=8, fixed and structure-aware chunking retrieved 83.8% of
labeled facts; sentence-window retrieved 89.2%, but created 173 chunks instead
of 19 and repeated 93.8% of parent-passage characters. It therefore remains an
experimental quality leader rather than the default.

On the exact-term synthetic corpus, lexical retrieval scored 100% document
recall, 75.7% fact recall, and 0.917 MRR; hybrid matched recall but scored 0.778
MRR because the 32-dimensional local dense channel degraded ordering. Adaptive
query expansion raised fact recall from 75.7% to 78.4%. Deterministic reranking
raised it to 83.8% and MRR to 1.000. K=16 or 1,800-character chunks separately
reached 100% retrieval fact recall but increased mean packed context.

Keyword GraphRAG recovered two of three expected relations; intent-multihop
recovered all three with valid source provenance. The current full
deterministic pipeline scored 0.917 quality and failed fact/graph thresholds.
Both advanced full variants scored 1.000 and passed deterministic gates; the
structure-aware variant was selected because it avoided sentence-window's
duplication and had lower latency. These are synthetic deterministic results,
not live-model or production-readiness claims. Full per-case evidence is in
`reports/staged-rag-evaluation.json` and the review report is in
`reports/staged-rag-evaluation.md`.

The final post-change 1K benchmark completed ingestion in 0.723 seconds at

## Generated Contextual RAG evaluation: 2026-09-12

Command: `./scripts/run.sh contextual-rag-evaluate --name
contextual-rag-qwen3-focused --chat-model qwen3:8b --embedding-model
qwen3-embedding:4b --top-k 8 --no-resume`.

The focused live run generated 23/23 query-independent contexts with no schema
or exact-entity grounding failures. Context generation took 14.811 seconds of
summed model latency, consumed 31,540 prompt and 866 output tokens, and produced
151.7 characters per context on average. Combined active Ollama allocation was
12,843,231,476 bytes, below the 17-GiB gate. All source spans and tenant scopes
remained valid.

The targeted multi-chunk case hid `USD 6,400.00` in a late chunk that omitted
`BOREALIS-204` and “funding.” Raw and deterministic-metadata retrieval missed
that fact at K=8 in every lane. Generated context recovered it at rank 4 with
lexical retrieval, rank 5 with local hybrid, rank 2 with Qwen dense retrieval,
and rank 3 with Qwen hybrid retrieval.

The benefit did not generalize to the full corpus. Three cached-context repeats
kept metadata plus Qwen hybrid fact Recall@8 at 0.8158, while generated-context
hybrid produced 0.7895, 0.7105, and 0.7105. Generated fact MRR was 0.3604,
0.3422, and 0.3291 versus metadata's 0.3494, 0.3483, and 0.3494. The targeted
fact remained at rank 3 in all three generated-context repeats, so the desired
cross-chunk behavior was stable even while exhaustive long-ledger coverage was
not.

Endpoint vector digests changed across fresh model loads despite identical
model/input/context digests; repeated calls within one load were byte-identical.
Endpoint-hybrid p50 also ranged from 341 to 399 ms, so no latency comparison is
claimed. Metadata indexes used 950,272-954,368 bytes and generated-context
indexes used 962,560-966,656 bytes; indexed text was deterministically 19,643
versus 22,017 characters. Generated context is therefore not promoted as a
global default. It is useful only behind semantic/cross-chunk routing, while
exhaustive queries keep deterministic range coverage. Full prompts, outputs,
contexts, rankings, vector digests, and source spans are in
`reports/contextual-rag-qwen3-focused.*` and
`reports/contextual-rag-qwen3-repeat-{1,2,3}.*`.

## Selective decomposition on synthetic email: 2026-09-13

Command:

```sh
./scripts/run.sh email-rag-evaluate \
  --chat-model qwen3:8b \
  --embedding-model qwen3-embedding:4b \
  --top-k 8 \
  --repeats 3 \
  --name email-rag-qwen3-final \
  --cache-name email-rag-qwen3-v1
```

The pinned corpus contains 180 synthetic email-like messages and 13 cases with
26 labeled facts. Eight cases route directly, four genuinely multi-part cases
route through cached model decomposition, and one all/every case uses a
canonical thread range. The suite includes revisions, attachments,
cross-message answers, semantic paraphrases, multilingual text, prompt
injection, 150 distractors, no-answer behavior, and a cross-tenant record.

| Method | Document recall | Retrieval fact recall | Fact MRR | Answer fact recall | Correct cases | Citation precision | Abstention accuracy |
|---|---:|---:|---:|---:|---:|---:|---:|
| Direct hybrid | 0.9697 × 3 | 0.8462 × 3 | 0.5468 × 3 | 0.8462 × 3 | 12/13 × 3 | 1.000 × 3 | 1.000 × 3 |
| Selective | 1.000 × 3 | 1.000 × 3 | 0.5617 × 3 | 1.000 × 3 | 13/13 × 3 | 1.000 × 3 | 1.000 × 3 |

Direct K=8 retrieved only eight of twelve `ATLAS-900` action messages, giving
22/26 aggregate retrieval and answer facts. Scope-locked thread-range retrieval
returned all twelve in timestamp/ID order. An explicit exhaustive coverage
prompt and omission validator then produced all twelve facts in all three live
repeats. Decomposition preserved both expected documents and facts for each of
the four multi-part cases; in this corpus direct retrieval already found those
eight facts, so the aggregate recall gain comes from thread-range coverage, not
from decomposition.

The initial answer-contract smoke appeared to score 1/26 facts because Qwen
usually returned field-qualified values such as `review_room: Sapphire Room`
instead of the exact value `Sapphire Room`. Raw prose, fact IDs, and citations
were otherwise correct. The validator now canonicalizes only when the model's
value contains the exact value found under the same fact ID in a cited passage,
and preserves both original and canonical values. It performed 21 such
normalizations in the selective lane per repeat. A second smoke reached 25/26
but omitted the twelfth exhaustive item; the final coverage contract made this
omission explicit and corrected it. All smoke artifacts remain under
`reports/email-rag-qwen3-smoke*`.

Selective aggregate retrieval p50 was 64.23-64.69 ms versus 61.82-63.83 ms for
direct. This aggregate hides routed-case cost: the four decomposed searches
took 184-194 ms after cached transformation, while estimated first-query cost
was 575-594 ms for three cases and 2.12 seconds for the slowest cached
transformation record. Thread-range retrieval took 0.36-0.41 ms. Final-answer
p50 was 1.128, 1.128, and 1.106 seconds; p95 was 2.093, 2.033, and 2.061
seconds. Each repeat made 18 unique answer calls and recorded approximately
23.2K prompt tokens, 2,530-2,536 output tokens, and 28.2-28.5 seconds of summed
model time.

Peak Ollama-reported active allocation was 12,843,231,476 bytes, below the
17-GiB cap. Whole-GPU telemetry reached 17,553,162,240 bytes but is not the cap
defined for this evaluation. Tenant scope, source spans, structured output,
grounded-fact precision, and citations were all 1.000 in every lane and repeat.
Both negative cases abstained in every repeat even though unthresholded hybrid
retrieval still returned irrelevant passages.

Fresh-load query-vector digests were identical in all three repeats, but the
180 document-vector digest differed each time. Retrieval and answer metrics
nevertheless remained rank-stable. The candidate therefore advances only to a
larger realistic evaluation; vector reproducibility and unlabeled real-mail
behavior remain unresolved. Full prompts, raw/canonical outputs, routes,
rankings, spans, vector digests, and runtime telemetry are in
`reports/email-rag-qwen3-final.json`; the review report is
`reports/email-rag-qwen3-final.md`.

The standard 1K baseline ingested in 0.726 seconds with 1.705 ms query p50,
2.126 ms p95, 32,120 KiB RSS, and a 3,420,160-byte database. Post-change values
were 0.728 seconds, 1.710 ms, 2.052 ms, 32,272 KiB, and the same database size.
These are single-run changes of approximately +0.28% ingestion, +0.28% p50,
-3.47% p95, and +0.47% RSS; no performance improvement or regression is

## Scale, stability, reranking, and parameter hardening: 2026-09-13

The final deterministic command was:

```sh
./scripts/run.sh scale-hardening-evaluate \
  --page-size 32 --reduction-batch-size 16 --repeats 3 \
  --name hardening-final
```

Every synthetic thread contains one independent fact per message, twelve
same-scope distractors, and one cross-tenant shadow. Direct top-8 fact recall
fell from 0.160 at 50 messages to 0.080, 0.032, and 0.016 at 100/250/500.
Canonical full, paged, and hierarchical paths retained 1.000 fact/document
recall, stable order, no duplicates, valid source spans, and scope integrity at
every size.

| Messages | Ingest ms | DB bytes | Full chars | Pages | Page peak chars | Hierarchy p50 ms | Hierarchy peak Python bytes |
|---:|---:|---:|---:|---:|---:|---:|---:|
| 50 | 38.425 | 344,064 | 15,141 | 2 | 9,687 | 3.012 | 54,035 |
| 100 | 67.821 | 536,576 | 30,392 | 4 | 9,728 | 5.882 | 101,884 |
| 250 | 165.858 | 1,101,824 | 76,142 | 8 | 9,760 | 15.488 | 272,464 |
| 500 | 327.784 | 2,031,616 | 152,392 | 16 | 9,760 | 30.752 | 529,356 |

Reduction batches 4, 8, 16, 32, and 64 all retained 1.000 fact recall on the
500-message thread. Batches 4/8 held the reduction working set below the page
peak, while 16/32/64 raised peak stage text to 13,484 characters. Batch 16 is a
throughput-oriented test default; batch 8 is the lower-memory candidate. The
hierarchy uses deterministic extraction/reduction, so it does not prove that a
generative summarizer will retain 500 unlabeled real-email facts.

Normalized parent storage preserved exact rankings and quality in three
repeats. The duplicated database was 569,344 bytes with 179,594 passage
characters; normalized storage was 356,352 bytes with 11,072 stored parent
characters, a 37.410% database reduction. Median ingest changed from 12.702 to
13.116 ms (+3.3%) in these tiny runs, so no ingest speedup is claimed. Artifact:
`reports/hardening-final-storage.*`.

The deterministic one-factor sweep provisionally selected 1,800-character
chunks, zero overlap, K/context-record depth 12, 1,200 characters per record,
14,400 total packed characters, eight retrieval candidates, and RRF 60. These
use local 32-dimensional control vectors and are live-validation candidates,
not Thunderbird defaults. Artifact: `reports/hardening-final-parameters.*`.

Embedding drift was measured with `qwen3-embedding:4b` over all 180 synthetic
emails and 13 queries across three fresh loads. Batch 24 took 6.85–6.95 seconds
per document pass. It was not exact within a load, after warm-up, or across
loads; minimum cosine was 0.997264. Cross-load exact ranking rates were 0.538
and 0.769 versus load one, while mean overlap@8 was 0.971 and 0.981. Fact and
document recall did not change, so the >=0.95 overlap and <=0.01 quality-delta
tolerance passed.

Batch 1 took 25.99–26.70 seconds per pass. Its cold first pass differed slightly
from the second (minimum cosine 0.999101), but second and third passes were
byte-identical in all three loads. The same request sequence also produced
identical vectors and rankings across fresh loads. This supports a
warm-once/singleton/persist strategy where exact rebuilds matter; batching is
acceptable only behind the measured tolerance. Peak Ollama allocation was
6,455,432,314 bytes. Artifacts: `reports/embedding-drift-final.*` and
`reports/embedding-drift-singleton-final.*`.

The true cross-encoder used TEI 1.9.3 with
`Alibaba-NLP/gte-reranker-modernbert-base`, float32, 8,192-token input, and CPU
execution (zero model VRAM). All repeats preserved candidate sets, scope, and
source spans. Across candidate depths 8/16/32/64, fact recall@8 stayed 0.9697;
fact MRR improved from 0.7933 without reranking to 0.8388. Mean CPU
cross-encoder p50 was 281, 557, 1,086, and 2,159 ms. Depth 8 is the measured
candidate because deeper pools gave no quality gain. GPU TEI could not be run
because Docker has no NVIDIA device driver. The idle CPU TEI container used
9.327 GiB of host RAM, so zero VRAM does not imply low resource cost. Artifacts:
`reports/cross-encoder-candidates-{8,16,64}-final.*` and
